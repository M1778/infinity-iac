Documentation / Introduction
GitHub

Infrastructure, with a reviewable path.

Infinity-IaC is a Go CLI for Oracle Cloud Infrastructure. Inspect an embedded recipe, review a plan, and provision with explicit access and lifecycle controls.

This documentation follows the source tree. It distinguishes runnable definitions, incomplete templates, and tested behavior. An accepted OCI launch is not an application readiness result, and a recipe count is not a deployment certification.

Installation

Choose a release binary for your platform. The Unix installer supports Linux and macOS on amd64 and arm64; Windows uses a per-user setup program. Published checksums are verified before installation.

Linux and macOS

Download the installer so you can read it before executing it.

Unix shell
curl -fsSL https://raw.githubusercontent.com/M1778/infinity-iac/master/install.sh -o install.sh
sh install.sh --prefix "$HOME/.local/bin"
"$HOME/.local/bin/infinity-iac" --version

Add the installation directory to PATH when prompted. To pin an available release, pass --version vX.Y.Z; confirm that tag exists in GitHub Releases first.

Windows installation

Download infinity-iac-setup.exe from a published release. Setup installs for the current user and offers a user PATH entry. Open a new terminal afterward and run infinity-iac --version. Uninstalling the CLI is not cloud-resource cleanup.

Build the current source

Use Go 1.23 or newer from the repository root. A source build can contain features not yet available through the installer.

Go build
go build -trimpath -o bin/infinity-iac ./cmd/infinity-iac
./bin/infinity-iac --version

When using sudo, select this binary explicitly, for example sudo ./bin/infinity-iac …. Root may resolve an older system-wide executable.

Configure OCI access

Use the standard OCI CLI credential file and an existing deployment subnet. Setup performs read-only checks before saving identifiers and the selected profile name. It does not copy your private key or create cloud resources.

  1. Configure the OCI CLI and confirm the selected profile can authenticate.
  2. Choose a compartment, subnet, availability domain, image, and compatible shape in the same region.
  3. Supply an SSH public key and save a named Infinity-IaC access profile.
Replace resource identifiers
infinity-iac setup oracle --autodetect \
  --name default --profile DEFAULT \
  --compartment COMPARTMENT_OCID --subnet SUBNET_OCID \
  --availability-domain AVAILABILITY_DOMAIN \
  --image IMAGE_OCID --shape VM.Standard.A1.Flex \
  --ssh-public-key "$(cat ~/.ssh/id_ed25519.pub)"
infinity-iac list acc
infinity-iac doctor --output json

--autodetect locates a readable OCI config and derives its region and tenancy. It does not guess deployment IDs or choose a billable shape. An explicit --config or OCI_CONFIG_FILE takes precedence and is not silently replaced when invalid.

Root-owned OCI credentials

If the OCI config and referenced key belong to root, run the explicit CLI binary as that user. Keep a separate Infinity-IaC config for test automation rather than overwriting your normal profiles.

Explicit binary and config
sudo OCI_CONFIG_FILE=/root/.oci/config ./bin/infinity-iac \
  setup oracle --autodetect --name test \
  --compartment COMPARTMENT_OCID --subnet SUBNET_OCID \
  --availability-domain AVAILABILITY_DOMAIN \
  --image IMAGE_OCID --shape VM.Standard.A1.Flex

Do not make a private key world-readable or copy it into a recipe, repository, guest VM, or CI variable to work around permissions.

The configured image OCID determines the guest OS; an OS label does not download or select a different image. Validate architecture and memory compatibility before provisioning.

Create and inspect

Billable create
infinity-iac create server --name demo --access default \
  --cpu 2 --ram 4GB --storage-size 50GB --yes
infinity-iac list instances --output json
infinity-iac run --recipe nginx --name web-demo --port 8080 --yes

Exactly one of --app, --script, or --recipe selects a recipe. Instance-target recipes provision a new VM; they are not commands to run on an arbitrary existing server. OCI boot volumes have a provider minimum, so the actual requested allocation can exceed a smaller recipe storage value.

Typed recipe inputs

Pass a JSON or YAML object with --inputs FILE. Values are checked against the recipe's declared types, required fields, and bounds before execution. --port is a service-port override; do not supply an unknown input key or use the input file as executable shell.

Validate inputs offline
infinity-iac recipe render --name nginx --inputs inputs.yaml
infinity-iac run --recipe nginx --access default \
  --inputs inputs.yaml --dry-run --output json

Rendering supplied sensitive inputs requires the explicit --include-sensitive opt-in. Use owner-only files and do not send rendered secrets to terminal logs, issues, or CI. A dry-run describes execution without creating a VM or executing a local script.

Review a plan before applying

Review, then apply
infinity-iac plan --file infrastructure.yaml --output json
infinity-iac apply --file infrastructure.yaml \
  --hash REVIEWED_PLAN_HASH --yes --output json

Use the hash returned by the reviewed plan. A changed manifest must be reviewed again; do not automatically approve an unexpected plan. Plans describe the implemented actions, not an implicit destroy of resources omitted from the file.

Shell completion and local unlink
Local operations
infinity-iac completion bash
infinity-iac completion fish
infinity-iac unlink acc test --yes

Completion also supports Zsh and PowerShell. Unlinking a profile leaves OCI credentials, instances, volumes, and networks unchanged.

Networks & instance lifecycle

A VM needs a compatible subnet, routes for required outbound access, and deliberately scoped ingress. The application catalog uses loopback bindings; network creation does not mean exposing every service to the internet.

Check the installed version. Managed network commands and extended instance lifecycle support are part of the 1.1.0 source target. The older 1.0.1 release requires an existing VCN/subnet and supports stop, restart, and delete. Use the matching source command reference until a new tag is published.

Managed network workflow

The managed network namespace provides create, list, get, update, and delete. Creation binds the VCN, subnet, gateway, routing, and security resources to an access profile; updates and deletion must reject resources that do not have matching ownership and association.

  • Choose non-overlapping VCN and subnet CIDRs.
  • Restrict SSH to your current source CIDR, normally a single /32.
  • Review the full route and rule changes before confirmation.
  • Delete dependent owned resources in order; foreign children are not adopted or removed.
Network-only profile and explicit SSH source
infinity-iac setup oracle --autodetect --network-only \
  --name network-admin --compartment COMPARTMENT_OCID
infinity-iac network create --name demo-net --access network-admin \
  --cidr 10.88.0.0/16 --subnet-cidr 10.88.1.0/24 \
  --ssh-source YOUR_PUBLIC_IP/32 --yes
infinity-iac network list --access network-admin --output json
infinity-iac network get NETWORK_ID --access network-admin
infinity-iac network update NETWORK_ID --access network-admin \
  --ssh-source YOUR_PUBLIC_IP/32 --yes
infinity-iac network delete NETWORK_ID --access network-admin --yes --wait

Replace YOUR_PUBLIC_IP/32 with your actual current source CIDR, not a public wildcard. Keep the resulting subnet identifier for a full compute setup profile. An application recipe's ingress metadata is not permission to modify a personal VCN or open its ports publicly.

Instance lifecycle

Owned instance only
infinity-iac instance get INSTANCE_ID --access default
infinity-iac instance stop INSTANCE_ID --access default --yes --wait
infinity-iac instance start INSTANCE_ID --access default --yes --wait
infinity-iac instance restart INSTANCE_ID --access default --yes --wait
infinity-iac instance delete INSTANCE_ID --access default --yes --wait

Use --wait and a bounded --timeout when an automated step needs a completed lifecycle state. Distinguish an accepted operation from confirmed completion. Confirm that a stopped VM is actually running again before probing its app, and confirm termination and boot-volume cleanup before declaring a test finished.

Deletion is not a backup. Terminating a VM with its boot volume removes local Docker volumes and application data. Export backups before deletion, and preserve cloud resource IDs until cleanup has been independently checked.

oc-hunter: local capacity helper

The 1.1.0 source target includes oc-hunter, inspired by oracle-freetier-instance-creation. It uses local OCI credentials and bounded attempts to create one explicitly requested instance when capacity becomes available.

  • Review the shape, memory, storage, domain selection, retry interval, attempt limit, and deadline before starting.
  • Retry capacity or throttling failures conservatively; stop for invalid configuration, authorization, quota errors, or cancellation.
  • Stop after one successful launch, and reconcile ambiguous responses rather than launching duplicates.
  • Do not copy credentials into cloud-init, leave an unattended hunter running, or assume a free-tier shape guarantees zero cost.

Go API

The public API target exposes the stable recipe and domain types through an infinityiac facade in the same Go module. Provider operations must retain context deadlines, ownership checks, and standard OCI credential loading; raw unchecked SDK mutations are not the public boundary.

Module dependency
go get github.com/M1778/infinity-iac@vX.Y.Z

Select a published module tag containing the public facade. Older versions put implementations under internal/, which cannot be imported by another module. Do not work around that restriction by copying provider internals or secret-bearing configuration into your application.

Recipe discovery/rendering and plan construction are offline entry points. The root package exposes BuiltinCatalog, RenderCloudInit, RenderLocalScript, and NewPlan, along with recipe, plan, instance, request, and network types. Package and compatibility guidance

Access, backups & test safety

Connect over a private application binding

For a service listening on the remote host's loopback port 8080, use an SSH tunnel. The subnet should admit SSH from your source, not from every address.

SSH tunnel
ssh -N -L 8080:127.0.0.1:8080 ubuntu@INSTANCE_PUBLIC_IP

Open the local forwarded address in your browser. An onboarding screen is not a completed administrator setup. Configure authentication, TLS, and backups before making an app externally accessible.

Keep secrets and resource ownership separate

  • Store OCI config and referenced keys with owner-only permissions. Infinity-IaC stores identifiers, not the private key.
  • Generated application secrets belong in owner-only files on the instance. Catalog outputs describe paths; they do not retrieve secret values.
  • Third-party recipes can execute arbitrary root commands. Installing a recipe is not approval to run it: inspect its sources and uploads first.
  • Never adopt a personal VCN, instance, volume, or container because its name resembles a test resource. Verify ownership and exact IDs.

Finish a live test with verified cleanup

  1. Create a separate run-tagged network and establish a working cleanup path before launching a VM.
  2. Record exact resource IDs immediately, including the instance and boot volume. Use a bounded deadline and independent cleanup fallback.
  3. Probe application readiness, restart behavior, and persistence; keep schema checks and runtime outcomes distinct.
  4. Delete only the run's owned resources, verify they are gone, and verify personal resources are unchanged.

Ordinary CI must not enable billable integration tests. Never publish credential files, SSH private keys, cloud journals, raw cloud output, or application passwords in issues or build logs.

Troubleshooting

A command or flag is missing

Run infinity-iac --version and check which binary your shell resolves. The installer downloads a tagged release, not your checkout. Root and your user can have different binaries on PATH. Use the explicit source-built path for unreleased features.

OCI config is unreadable or access validation fails

Check the exact profile and readable config path, then the private-key path referenced by that profile. Confirm region, compartment, subnet, image, availability domain, and shape compatibility. An explicit invalid config is not silently replaced. Fix access and identifiers without printing key material.

A recipe is blocked or needs inputs

Expand its catalog entry and inspect status, requirements, and required input names. A template cannot render or launch. An external domain, credential, database, cluster, or GPU requirement must be satisfied explicitly; changing the status label is not a deployment fix.

The VM is running but the application is not ready

Inspect cloud-init status --long, cloud-final logs, and the recipe's readiness marker at /var/lib/infinity-iac/ready/RECIPE. Check outbound package/image access and the real HTTP or database probe. Do not rerun cloud-init blindly or treat Docker process liveness as application success.

Capacity, quota, or tool-execution errors

Capacity retry is not permission to evade quotas. Stop on authorization or limit faults and use a bounded interval for capacity retries. A local command runner failure is separate from an OCI ingress rule; opening all protocols will not fix a local tool blocker.

A delete request succeeded but resources still appear

Wait for the terminal lifecycle state and inspect exact instance, boot-volume, subnet, gateway, and VCN IDs. Resource deletion can be asynchronous. Keep the journal until absence is verified; do not broaden cleanup to every resource in the compartment.

Source target: 1.1.1. The 1.1.0 release was blocked by its Windows uninstall check; a tag alone does not provide installer assets. Check release assets and notes for the version available to installers. Merging source changes alone does not update installer downloads.

Opt-in live tests add evidence for the tested OCI and application lifecycle. Neither path certifies untested hardware, every architecture, external integrations, production authentication, or recovery from an absent backup.
